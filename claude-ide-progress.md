## Отклонения от T8-спеки

- Имя правого буфера — `✻ <file> [<pid>]` как в спеке, но язык подсветки выставляется явно по целевому пути (`Loader::language_for_filename` + `Document::set_language`): суффикс `[pid]` ломает детект по расширению.
- Таблица клиентов вынесена в `clients.rs` и делится между транспортом и диспетчером (`Arc<Clients>`), а не хранится в `Shared` — диспетчеру нужен доступ к pid/permission-mode без обратной ссылки.
- `show_lock` (один prompt на экране) остаётся, но в split-режиме отключается флагом `EditorHandler::set_exclusive_display(false)` (helix-term выставляет его по `diff-mode` при старте и при каждом `OpenDiff`): иначе «два split-а одновременно» из спеки §2/§4 невозможны.
- Replay выделения для нового соединения пропускается, если после подключения уже был broadcast — иначе клиент получал один и тот же `selection_changed` дважды (сломало `claude_ide_integration`).
- `:claude-ide-status` с клиентами показывается popup-ом (`ui::Text`), без клиентов — прежней строкой статуса.
- Фокус (`:claude-ide-focus`) хранится в `EditorHandler`, а не в `Editor`: сброс при отключении клиента происходит в `on_client_disconnected`.
- cwd по pid реализован только для Linux (`/proc/<pid>/cwd`), как и предписано; на macOS показывается `?`.

## Наблюдения по реальному CLI 2.1.261 (уточнения к PROTO)

- **CLI переподключается сам** после разрыва WebSocket (`WebSocket transport closed/disconnected, attempting automatic reconnection`, попытки с backoff 1 с, 2 с, …) — PROTO §2.6 утверждает обратное. Для Helix это значит, что после `:claude-ide-stop`/`:claude-ide-start` на том же порту CLI вернётся сам.
- CLI вызывает инструмент **`set_permission_mode {mode}`** при смене режима разрешений (`callIdeRpc("set_permission_mode", …)`, ошибки глотает) — в PROTO не описан; Helix отвечает `-32602 Tool not found`, это безвредно. Кандидат на no-op-реализацию в T7.
- Ошибочный результат `isError:true` от `closeAllDiffTabs` CLI пишет в debug-лог как `[ERROR]`, но продолжает работу (до T5 инструмент — заглушка).
- Диагностики отражают **буфер Helix**: после правки файла CLI-инструментом Edit открытый в Helix документ не перечитывается, LSP видит старое содержимое, поэтому «новые диагностики» появятся только после `:reload`. В T5 после `FILE_SAVED` стоит перечитывать документ автоматически (файл на диск пишет CLI).
- **`openDiff` — часть permission-flow CLI**: вызывается только когда CLI спрашивает разрешение на Edit/Write (режим `default`, не `acceptEdits`/`plan`/`bypassPermissions`), при подключённой IDE и `diffTool == "auto"` (ключ глобального конфига `~/.claude/.claude.json`, **по умолчанию уже `"auto"`**, а не `settings.json`, как сказано в tasks.md). Параллельно CLI показывает свой терминальный prompt («Opened changes in <ide> ⧉ · 1. Yes …»); кто ответит первым, тот и решает — после ответа в терминале CLI шлёт `close_tab`. Настройка `defaultMode: "plan"` в settings.json пользователя переводит вложенный CLI в plan mode — для проверок нужен `--permission-mode default`.
- `claude -p` (print-режим) к IDE не подключается; при вводе через pty текст и `\r` нужно слать раздельно, иначе Enter трактуется как часть вставки и промпт не отправляется.
- **Отказ до апгрейда (HTTP 503) CLI не повторяет**: `MCP server "ide": Connection failed after 13ms: … Expected 101 status code`, одна попытка, IDE помечается как failed. Авто-переподключение с backoff срабатывает только для соединения, которое было установлено и затем закрыто. Поэтому лимит `max-clients` не порождает ping-pong (T8).
